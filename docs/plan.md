# NATS Evaluation — Consolidated Master Plan

| Layer                                | Domain                      | Evaluation Area                | Sub-topics                                                                                                                                                        |
| ------------------------------------ | --------------------------- | ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **L1 — NATS Internals & Deployment** | **Core Architecture**       | Server & Protocol              | Server architecture, internal components, client-server communication, wire protocol, connection lifecycle, message routing                                       |
| L1                                   | Core Architecture           | Clustering & Routing           | Cluster formation, routes, cluster topology, server discovery, cluster membership, inter-server communication, routing                                            |
| L1                                   | **JetStream Internals**     | Architecture & Data Flow       | JetStream architecture, control/data plane, stream internals, consumer internals, metadata, message lifecycle                                                     |
| L1                                   | JetStream Internals         | Write & Persistence Path       | Publish → JetStream → replication → persistence → acknowledgement, write path, read path                                                                          |
| L1                                   | **Replication & HA**        | Consensus & Replication        | RAFT, leader election, quorum, log replication, commit, replica placement, leader/follower behaviour, synchronisation                                             |
| L1                                   | Replication & HA            | Failure & Recovery             | Server failure, leader failure, replica failure, quorum loss, network partition, restart, replica catch-up, recovery, consistency                                 |
| L1                                   | **Storage**                 | Storage Architecture           | File store, memory store, persistence, storage layout, storage lifecycle                                                                                          |
| L1                                   | Storage                     | Storage Performance            | I/O behaviour, throughput, latency, disk utilisation, memory utilisation, storage growth                                                                          |
| L1                                   | **Deployment & Operations** | Runtime Architecture           | VM/bare-metal, Kubernetes, StatefulSet, networking, service discovery, persistent volumes, resource sizing                                                        |
| L1                                   | Deployment & Operations     | Security Infrastructure        | TLS, certificates, server authentication, credentials, secrets                                                                                                    |
| L1                                   | Deployment & Operations     | Backup & DR                    | Backup, restore, object storage, RPO/RTO, disaster recovery                                                                                                       |
| L1                                   | Deployment & Operations     | Lifecycle & Upgrades           | Startup/shutdown, configuration changes, rolling upgrades, version compatibility, maintenance, troubleshooting                                                    |
| **L2 — NATS Platform Abstraction**   | **Streams**                 | Lifecycle                      | Creation, update, sequence handling, retention handling, cleanup, deletion, sealing, pause/resume, backup/restore, separate-stream criteria, ownership            |
| L2                                   | Streams                     | Storage                        | File vs memory, storage capabilities, operational characteristics, performance, storage limits, retention options, storage growth, backup to object store, sizing |
| L2                                   | Streams                     | Configuration                  | Subjects, retention, discard policy, max age, max bytes, max messages, max message size, duplicate window, replication factor, storage type                       |
| L2                                   | Streams                     | Reliability                    | Replication, durability, failure tolerance, quorum requirements, duplicate handling, ordering, recovery                                                           |
| L2                                   | Streams                     | Observability                  | **Health, resource consumption, overload conditions, replication status**, throughput, storage utilisation, publish failures, capacity, alerts                    |
| L2                                   | Streams                     | Governance & Abstraction       | Naming, ownership, tenant isolation, quotas, limits, RBAC, platform defaults, developer-configurable vs platform-controlled options                               |
| L2                                   | **Consumers**               | Lifecycle & Configuration      | Creation, update, deletion, durable/ephemeral, ownership, delivery policy, replay policy, filtering                                                               |
| L2                                   | Consumers                   | Delivery & Acknowledgement     | Pull/push, Ack, Nak, Term, InProgress, AckWait, MaxDeliver, Backoff, redelivery                                                                                   |
| L2                                   | Consumers                   | Reliability & Observability    | Consumer failure/recovery, lag, slow consumers, backpressure, delivery rate, ack rate, redelivery, pending messages, errors                                       |
| L2                                   | Consumers                   | Governance                     | Consumer limits, quotas, naming, ownership, access control, allowed configurations                                                                                |
| L2                                   | **Platform Security**       | Identity & Access              | Authentication, credentials, TLS, accounts, permissions, publish/subscribe access, stream/consumer access                                                         |
| L2                                   | Platform Security           | Multi-tenancy                  | Tenant isolation, account isolation, environment isolation, resource ownership                                                                                    |
| L2                                   | **Platform Management**     | Provisioning & Lifecycle       | Application onboarding, stream/consumer provisioning, self-service, API, GitOps, automation, resource lifecycle                                                   |
| L2                                   | Platform Management         | Resource & Policy Management   | Quotas, capacity, limits, resource allocation, configuration policies, cost management                                                                            |
| L2                                   | Platform Management         | Platform Observability         | Platform metrics, logs, dashboards, alerts, SLOs, health monitoring                                                                                               |
| L2                                   | Platform Management         | Backup & DR                    | Backup policy, frequency, retention, restore ownership, RPO/RTO                                                                                                   |
| **L3 — Developer Consumption**       | **Messaging**               | Messaging Model                | Subjects, hierarchy, naming, wildcards, publish/subscribe, queue groups, request/reply                                                                            |
| L3                                   | Messaging                   | Message Model                  | Payload, headers, reply subject, metadata, message ID, correlation ID                                                                                             |
| L3                                   | **SDK**                     | SDK Capabilities               | Go, Java, Python, JavaScript/TypeScript, publish, subscribe, request/reply, queue groups, JetStream APIs                                                          |
| L3                                   | SDK                         | Connection & Error Handling    | Connection establishment, authentication, reconnect, disconnect, timeout, publish errors, subscription errors, connection errors                                  |
| L3                                   | SDK                         | Application Behaviour          | Async APIs, concurrency, retry, idempotency, duplicate handling, graceful shutdown                                                                                |
| L3                                   | **CLI**                     | Messaging Operations           | Publish, subscribe, request, reply                                                                                                                                |
| L3                                   | CLI                         | Stream & Consumer Operations   | Create, update, delete, info, list, inspect, backup, restore                                                                                                      |
| L3                                   | CLI                         | Troubleshooting                | Stream inspection, consumer inspection, message inspection, monitoring, connectivity debugging                                                                    |
| L3                                   | **Application Patterns**    | Messaging Patterns             | Event-driven, event fan-out, work queues, competing consumers, request/reply, service communication                                                               |
| L3                                   | Application Patterns        | Reliability Patterns           | At-most-once, at-least-once, idempotency, retry, duplicate handling, DLQ, backpressure, timeout                                                                   |
| L3                                   | **Developer Experience**    | Onboarding & Documentation     | Credentials, connection, stream/consumer usage, local development, getting started, SDK examples, CLI examples                                                    |
| L3                                   | Developer Experience        | Application Observability      | Metrics, logging, tracing, correlation, error diagnosis                                                                                                           |
| L3                                   | Developer Experience        | Best Practices & Anti-patterns | Subject design, stream usage, acknowledgement practices, retry behaviour, duplicate processing                                                                    |
